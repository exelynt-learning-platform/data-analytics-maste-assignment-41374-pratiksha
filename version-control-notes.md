# Version Control, Git, and GitHub Fundamentals

## 1. What is Version Control and why is it important?

Version control is used to keep track of changes made in a project. It saves different versions of the files, so if something goes wrong, we can check the previous version and restore it. It is also useful when many people are working on the same project.

## 2. Why do developers use Git?

Developers use Git to manage and track their code changes. They can work on different features using branches and later combine the changes. Git also helps developers go back to an older version of the code if needed.

## 3. Common problems Git solves

Git helps with problems like:

- Losing previous changes
- Accidentally changing or deleting code
- Knowing what changes were made
- Working on different features at the same time
- Multiple developers working on the same project
- Going back to an older working version

## 4. Difference between Git and GitHub

Git and GitHub are not the same.

Git is a tool used for version control. It is installed on our computer and helps us track changes in our project.

GitHub is an online platform where we can store Git repositories and share our code with others.

So, **Git is a version control tool, while GitHub is a platform for hosting and collaborating on Git projects.**

## 5. Centralized vs Distributed Version Control Systems

In a centralized version control system, the main project is stored on one central server. Developers connect to this server to get and update the code.

In a distributed version control system, every developer has a copy of the repository on their own computer. Git uses a distributed version control system.

| Centralized | Distributed |
|---|---|
| One central server | Each developer has a local copy |
| Requires connection to the central server for many operations | Many operations can be done locally |
| Example: SVN | Example: Git |
| If the central server has a problem, it can affect the team | Copies of the repository are available with developers |
